# 日経225オプション 建玉残高ダッシュボード

JPXが毎日公開する「デリバティブ建玉残高表」から、日経225オプション・日経225ミニオプションの
権利行使価格別建玉残高（プット/コール、当日・前日比）を取得し、Streamlitで可視化する。

## データソース

- [当日取引高等](https://www.jpx.co.jp/markets/derivatives/trading-volume/index.html) 内の
  「デリバティブ建玉残高表」（`*open_interest.xlsx`、毎営業日20:00頃更新）
- ファイルの別紙1＝日経225オプション（通常）、別紙2＝日経225ミニオプション、権利行使価格別
- ダウンロードURL（コンテンツID部分）は日によって変わるため、`fetch_open_interest.py` は
  毎回トップページを読んでリンクを見つけ直す
- **過去分の履歴はJPX側にアーカイブが無い**（1日分＝前日比のみ）。複数日の推移を見るには、
  このスクリプトを毎日実行してdata/に蓄積していく必要がある（GitHub Actionsで自動化）

## 使い方

### ローカル実行
```bash
pip install -r requirements.txt
python fetch_open_interest.py   # data/oi_history/YYYY-MM-DD.csv を作成
streamlit run app.py
```

### 自動更新（GitHub Actions）
`.github/workflows/fetch_daily.yml` が平日21:00 JST（JPX掲載予定20:00の後）に
`fetch_open_interest.py` を実行し、`data/` の新しいCSVを自動コミット・プッシュする。
リポジトリの Settings → Actions → General で "Read and write permissions" を
有効にしておくこと（`GITHUB_TOKEN` によるpushに必要）。

手動実行: Actions タブ → "Fetch daily open interest" → "Run workflow"

### Streamlit Cloud
1. このリポジトリをGitHubにpush
2. [Streamlit Cloud](https://streamlit.io/cloud) で `app.py` を指定してデプロイ
3. GitHub Actionsが`data/`を毎日更新するたびに、Streamlit Cloud側も自動で再デプロイされる
   （リポジトリ更新をトリガーに再起動する設定になっている場合）

## ダッシュボードの機能
- 権利行使価格別の建玉残高（プット/コール色分け棒グラフ）
- C-P差分（コール建玉残高-プット建玉残高）の横向きバーチャート。ストライクを縦軸に取り、
  C-P≥0は青（コール優位）、C-P<0はオレンジ（プット優位）で色分け。サイドバーの「現在値」
  「表示レンジ幅（±5,000〜±20,000円）」で、このチャートと権利行使価格別建玉残高チャート
  両方の表示範囲を現在値近辺に絞り込める
- 自分のポジション（プット買/売・コール買/売の権利行使価格）を縦線（横向きチャートでは横線）で重ねて表示
- 前日比の建玉増減（上位20銘柄、絶対値順）
- 複数日分蓄積された場合の、選択ストライクの建玉残高推移
- Put/Call比（建玉残高ベース）の日次推移（2日分以上たまると表示）
- マックスペイン価格（満期決済価格ごとのオプション買い手側支払総額が最小になる権利行使価格）の算出・表示、および複数日分たまった場合の推移
- **ガンママップ（モデルA・符号なし）** と加速ポイント候補（現在値±2,000円で上位5ストライク）。
  ヘッジの向きは不明（誰がどちら側かは公開データから特定できない）。詳細は `docs/261004_spec.md`
- 期近・次限月のストライク別建玉の前日比増減・直近5営業日のヒートマップ・上位5ストライク
- 手口（限定版）: 日次の取引参加者別取引高（売買区分なし・向き不明）と、週次の売超/買超
  （期近限月のATM近傍5ストライクのみ）。「業者側」の参加者一覧は `261004_participants.py`

## 追加データ（2026-10-04〜）

`261004_fetch_market_data.py` が `data/oi_history/` の各日付について、IV（`data/iv_history/`）、
日次の手口（`data/participant_volume/`）、週次の参加者別建玉（`data/participant_oi_weekly/`）を
未取得分だけ取得する（GitHub Actionsで毎日実行、バックフィルも同じコード）。
調査結果は `docs/261004_phase0_data_survey.md`。

## グラフの共通スタイル

`261004_chart_style.py` の `install()` を `app.py` の冒頭で呼んでおり、`st.plotly_chart`（列・タブ内を含む）に
共通のレイアウト（凡例の文字色=白、背景=透明）が自動で適用される。グラフを追加するときに
凡例の色を個別に書く必要はない。共通設定を変えたいときは同ファイルの `LEGEND_STYLE` を編集する。

## 制約・注意点
- 建玉残高は「概算」（JPXファイル自身に "（概算）" と明記）であり、確定値ではない
- 権利行使価格グリッドは限月・商品ごとに異なる（通常は250円刻み、ミニは125円刻み）
- **ミニオプションの限月コード（例: `260820`）はSQ日ではなく「取引最終日」を表すJPXの内部コード**。
  金曜限月は前営業日（木曜）、水曜限月は前営業日（火曜）が取引最終日になる規則
  （商品概要ページに明記）に対応しており、ダッシュボード上は最終取引日の翌暦日を
  「推定SQ日」として併記している（祝日を挟む場合はズレる可能性あり）。
- **ミニオプションは建玉残高表に直近5限月分程度しか掲載されない**（標準オプションは
  2609/2610/2611のように数ヶ月先まで載るが、ミニは同時上場数が多い分、近い範囲に限られる
  模様）。月次限月と同じSQ日を持つ第2金曜のミニ限月（例: 9月なら9/11）も、
  当日時点で3週間以上先だとまだ掲載されず、限月選択に出てこない。直近の限月が
  取引最終日を迎えて表から外れるにつれて、数日〜1週間程度で自動的に表示されるようになる
  （2026-08-19時点の観測: 直近5限月は8/20,8/25,8/27,9/1,9/3限の取引最終日分のみ）。
